# Distribution readiness — LARMOR 0.16.0

*Audit of 2026-10-05 for the first public distribution of the Windows build
(and, if the author decides so, of the repository): how every capability is
now checked inside the installed copy, what that check and a documentation /
licence / privacy audit found and fixed, and what remains the author's call.*

## 1 · How a build proves itself

Every capability of the program can be exercised inside the installed copy,
without Python, from the program folder:

```
LARMOR.exe --selftest                 fits a synthetic spectrum through the core and the window
LARMOR.exe --distcheck --quick        every module, resource, engine, export format, the pool, the CLI
LARMOR.exe --distcheck --gui --quick  the same, plus every window, tool and menu action, off screen
```

Both write `C:\Users\<you>\LARMOR_distcheck.log` (and a JSON twin) and end
with `=== PASS` or `=== FAIL: <stages>`. Without `--quick` the check builds
full-size lineshape kernels and runs every fit to the end. The check is
`larmor/distcheck/` (36 stages):

| stage group | what it proves, and against what |
|---|---|
| `environment` | interpreter, versions, where the resources are read from |
| `imports` | every module the source imports anywhere (`larmor/static/import_manifest.json`, regenerated by `python -m larmor.distcheck.manifest --write`; `tests/test_distcheck.py` fails when it is stale) plus the modules reached only through strings, listed by feature: matplotlib's file-format backends, pyqtgraph's exporters, Pillow's plugins, the process pool's spawn machinery, lmfit's registries |
| `resources` | every help page, tutorial, asset, static file, example file and fact-pack image is where the frozen build expects it, and the help viewer's own locators find them |
| `exports` | PNG / SVG / PDF / EPS through `larmor.figures.export`, TIFF / JPG through Agg and Pillow, the help renderer's PNG bytes |
| `pool` | a real process pool: twelve items through two worker processes whose process ids differ from the parent's (a frozen exe must re-enter its launcher as a worker, and the pool's sequential fallback must not be what passed) |
| `cli` | `--help` of every subcommand, then `info`, `acqtable`, `compare`, `inventory` on the bundled example data |
| `engine-*` (11) | every Qt-free capability, each result checked against something independent: readers (Bruker 1r / fid / 2D, Varian, CSV, dmfit import and export round trips), processing (every op, autophase, baselines including pybaselines), all 18 lineshape models, fitting (recovered positions and amplitudes against the synthetic truth), the error tools, constraints, multi-spectrum fits (multi-field, batch with released parameters, the series sweep), records (acquisition fields against acqus / procs read with a plain regex, comparability, inventory, referencing against IUPAC Ξ, provenance hashes against `hashlib`, recipes, projects, fit tables, series tables), specialist tools (T1 / T2 by five routes, REDOR against Mueller's closed form, Arrhenius, VOCS, QCPMG, shift calibration, DFT C_Q from CODATA, 3QMAS centroids against the analytic second-order shifts) and every figure kind with its geometry checked against the source numbers |
| `tool-*` (9) | the desktop workflows: open, apply a fit, fit, every save format, the publication bundle, the Plotting studio's every export format, the live plot's exporters, overlays, the series mode, the 2D view, the processing panel, a project round trip, the Explorer and Workspaces docks |
| `dialog-*` (5) | every tool window: error analysis, Monte-Carlo, χ² map, correlations, Czjzek distribution, comparison, integrals, Auto fit, batch fit and its outputs, the line and literature helpers, relaxation and wideline tools, the utility windows |
| `menu-*` (5) | every menu action (200) in three window states (a fitted spectrum, an empty one, the 2D map), every theme and text size, every manual and tutorial, every View toggle and dock |

Each GUI group runs in a child process with a fresh application; a crash in a
group is reported as that group's failure. Unless `--real-settings` is given,
a check never touches the user's own stores: the preferences go to a scratch
`.ini` (`LARMOR_SETTINGS_FILE`), `%LOCALAPPDATA%` and each store's override
variable point into a sandbox, and the environment is restored on the way out.
The same stages run in the development install as tests
(`tests/test_distcheck*.py`).

## 2 · What was found and fixed

**Packaging and licences**

- The frozen app had no `matplotlib.backends.backend_svg` (nor `_pdf`, `_ps`):
  the first SVG export from the Plotting studio crashed (the report that
  started this audit). PyInstaller follows imports, not
  `savefig(format="svg")`; the backends are now named in the spec and imported
  by every check.
- The bundle shipped `Qt6VirtualKeyboard.dll` (GPL-3.0-only, never loaded)
  and the QML / Quick stack it drags in; the spec filters them out with
  `Qt6Pdf` and `Qt6Test` (the bundle shrank to 340 MB).
- No licence text travelled with the binary, not even LARMOR's own, and the
  LGPL terms of Qt / PySide6 / shiboken6 were stated nowhere. `LICENSE`,
  `THIRD_PARTY_LICENSES.txt` (regenerated by every build from the build
  environment) and `LICENSES\LGPL-3.0.txt` / `GPL-3.0.txt` now sit next to the
  exe; README, `INSTALL.txt` and the About dialog state the terms.
- Two bird photos of the Help ▸ More… card could not be redistributed ("all
  rights reserved"; CC BY-NC-ND on a resized copy): removed;
  `CREDITS.txt` lists the twelve that remain.
- The example data set now ships inside the build; its Bruker comment lines,
  an `OWNER` field and two dmfit `FileName` elements carried the author's
  former accounts, host names and local paths and were scrubbed. Its two
  saved fits stored SR = 0 Hz against data referenced at −607.40 / −929.11 Hz,
  so reopening either reported a false "re-referenced since the fit".

**Results a user would publish**

- **REDOR distances were 26 % too long.** The isolated-pair dephasing ran
  twice too fast in λ (a 4√2 prefactor where the spin-½ pair gives 2√2), so
  every fitted coupling was half the true one. Now held to Mueller's closed
  form (ΔS/S0 = 0.5 at λ = 0.766, first maximum 1.043 at λ = 1.671), the
  Bertmer–Eckert short-time law (16/15)λ² and the van Vleck M2 = (2πD)²/5,
  verified with an independent implementation. **Any REDOR distance computed
  with an earlier LARMOR should be recomputed.**
- The Experimental paragraph said "a 3.1 µs pulse at 0 W" for an MQMAS
  (mp3qdfsz plays p1 at pl11 = 250 W; PLW1 was unused) and named a merged
  single-pulse + MQMAS group "single pulse acquisitions". It now states the
  power the pulse program plays p1 at, or none.
- Family populations in the independent-error basis left out the
  normalisation (a family holding every line read 100 ± 2.6 %); now proper
  first-order propagation, equal to the covariance basis at zero
  correlation.
- A DFT import seeded a negative C_Q, which the ≥ 0 bound clamped to
  0.01 MHz; it now seeds |C_Q|.
- `series.detect_kind` always returned None, so every caller relying on it
  fitted a saturation recovery, CPMG data included.
- The self-test's synthetic spectrum had its lines at the wrong ppm (a Czjzek
  simulation runs on the kernel's own axis).

**Desktop**

- Every SVG export of a live plot failed under Qt 6.11 (pyqtgraph 0.14 cannot
  parse Qt's bare closepath); fixed in the one export path.
- Process ▸ Reset to original kept the processing record of the chain it had
  just dropped; a saved fit replayed it.
- The Integrals dialog crashed before opening on a coarse spectrum (~1 ppm
  per point).
- Held parameter values never rendered dimmed (a stray brace in a style
  sheet made Qt refuse it).
- The first-run hint never showed.

**Start-up and the user's own data**

- A corrupt registry value stopped the application before its window existed;
  three registry values were parsed without a guard. Every read goes through
  `larmor/desktop/prefs.py` now, and `tests/test_startup_robustness.py` feeds
  garbage to every saved key.
- The crash log was truncated at every start, under two spellings of one
  name, wiping the previous crash before a user could send it; it is appended.
- The test suite and the check now use their own preferences file and their
  own `%LOCALAPPDATA%`. *During this audit, a test of mine overwrote the
  author's saved LARMOR preferences in the registry and then hung before its
  guard could restore them; the original values were lost (recent files,
  pinned Explorer folders, remembered line defaults, saved constraint sets,
  batch templates, theme). The isolation above exists so this cannot recur.*

**Documentation**

- README: the installer first, the self-checks, the bundled example, the
  0.15.3 series-mode behaviour, the licence section, the one network access.
- `INSTALL.txt` rewritten for a stranger: real menu names, the example path,
  where to report and with which files, `--distcheck --quick`, what an
  uninstall leaves behind, licences.
- Five menu paths / shortcuts corrected in the help pages and the first-run
  hint; worktree bookkeeping stripped from the tutorials; copyright holder
  and `pyproject` metadata made consistent.

## 4 · Known limitations, measured and left

- Window integration loses up to one grid step at each edge that cuts a line
  (−1.6 % of a line cut at 20 ppm); a fix would shift every windowed
  integral.
- `redor.GAMMA_MHZ_T` differs from the nuclide table (mrsimulator's) for
  ²⁰⁷Pb by 2.5 % and ³¹P by 0.1 % (< 1 % on a distance; published
  compilations disagree at that level for ²⁰⁷Pb).
- DFT-derived C_Q uses mrsimulator's quadrupole moments (²⁷Al 0.150 b, 2.3 %
  above Pyykkö 2018's 0.1466 b).
- `twod.fit_2d` with β free can stall when started far from the ridges.
- The check's GUI groups run in separate processes because, in one process,
  thirty GUI stages left enough closed windows behind for a later text-size
  switch to crash Qt; a realistic session does not (development notes §8).

## 5 · Decisions that are the author's

1. **Publishing the example data set.** `examples/pCABS2-4` is the author's
   own 2022 measurement from a former lab. After scrubbing, the files still
   reveal acquisition dates, a +0100 timezone, a probe identifier, French
   title lines and sample masses; no institution or third person is named.
   Confirm the right to publish it, or replace it.
2. **Bruker pulse programs** in the example (`zg`, `mp3qdfsz`) are Bruker's
   library files, routinely present in public Bruker data deposits; keep or
   delete (Tools ▸ Pulse program reads them).
3. **Non-commercial photo licences** (eleven of the twelve bird photos are
   CC BY-NC / CC BY-NC-SA) inside an MIT download: fine for this
   distribution, a problem for anyone redistributing commercially.
4. **The GitHub URL** in About, `INSTALL.txt`, the installer metadata and
   `pyproject` points at a private repository, and it is the only
   "report a problem" channel. Make it public (after moving
   `docs/workplan-status.md`, an internal session log, out of it and
   anonymising the test fixtures that quote the author's machine) or point
   these at a page that exists.
5. **The personal e-mail** in `pyproject` is written into every build's
   package metadata.
6. **Institutional copyright and acknowledgement**: the About dialog states
   DOE support and the installer publisher is the McCloy group; check WSU's
   software policy and the award's acknowledgement terms.
7. **Code signing**: the build is unsigned; SmartScreen warns, and
   `INSTALL.txt` explains the two clicks.
8. **The lost preferences**: the author's previous LARMOR preferences exist
   only in the memory of a hung test process (python.exe started 10:10 on
   2026-10-05), left running on purpose; recovering them means reading that
   process's memory, which the session's safety check declined to do.
